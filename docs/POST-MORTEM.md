# 状态总结与复盘 · 2026-10

> 这份文档回答三件事：**系统现在到底能做什么**、**这一段踩过的坑各自是什么根因**、
> **重做时哪些必须保留、哪些必须删掉**。技术细节看 [`DESIGN.md`](DESIGN.md)。

---

## 1. 现状：能做什么，不能做什么

**能**（每一条都在真机上跑过）：

- 自己开机：启动游戏 → 过标题 → 捏角色 → 建新档 → 进去干活 → 天黑回家睡觉。
- **在用户占用主屏、游戏留在副屏后台的情况下**完成上面全部（`is_active=False` 全程）。
- 农场基础活：清地、锄地、播种、浇水、收割（宏，游戏速度，可被新指令打断）。
- 进店买卖、开容器、读门上的营业时间、按名字找 NPC 说话、按任务目标推进。
- **自己发现并命名桥的缺陷**（回执 + 判词 + 桥的账），并从 `bridge_report` 走到 `bridge_patch` → 编译 → 探针 → 上线。

**不能 / 还没验证**：

- 后台状态下 `press_key`（escape 等）是否真被读到——**未实测**（同 `queue_read` 需要量一次）。
- 换一台机器或换窗口模式后，`queue_read=false` 这个事实需要重新量（它是**窗口级**事实）。
- 宏被打断后"旧活记进 `chore_last`、稍后回去干完"这条链路缺长跑验证。
- 视觉、OCR：**故意不做**（StarDojo 数据：给了图像+状态，GPT-4.1 成功率仍 12.7%，瓶颈在动作层与规划层）。

## 2. 这一段实际发生了什么（一句话一条）

1. 修好了买种子链路；随后发现**提示词里那条"商店营业时间"的规则其实是疤痕**，删掉，去测 agent 能不能自己挣到。
2. 玩家抱怨"太规则化、不像人"→ 把"规则"与"手册"分开：**规则 = 出 bug 后的疤；手册 = 新玩家必须被告诉的操作**。
3. 引入**尺子**（`world.steps_since_change`）：只报数，不设阈值、不附动作。
4. 玩家抱怨"进游戏后一直没操作"→ 一路挖到**躯体层**：点击的回答被扔掉、后台窗口不跑帧、物理鼠标在抢指针。
5. 今天最终把这一层重做：**禁用物理鼠标**，点击走"投递 → 直调菜单处理"，按键后台投递，永不抢焦点。
6. 玩家要求"新建存档"→ 暴露了 boot 流水线三个陈年 bug（见 §3 的 4/5/6 条）。
7. 玩家要求"agent 自己能发现并修桥"→ 落地：**回执 + 判词 + 修复层（编译门/探针门/回滚/裁判不可改）**。

## 3. 教训（每条都有实证）

### 3.1 桥必须自首：点击要回执

- **现象**：点击"成功"、世界没动，同一条动作每 10 秒重试，控制台一句话都没有。
- **根因**：三处调用点（bootstrap / runner / play 循环）**把动作的返回值扔了**。
- **证据**：`[流水线] 点 Load -> ok=False HANDLE_AMBIGUOUS | 'Load' matches 2 controls … use buttons#1`
  ——它把这个拒绝原样点了**四遍以上**。
- **现在**：回执是固定字段（`requested/resolved/unique/matches/candidates/verdict/changed/active`），
  所有调用点必须打印它。

### 3.2 名字不是句柄

- **现象**：`menu_click inventory.12` 命中了**容器那一排**，而 agent 想点自己背包那一排。
- **根因**：`ItemGrabMenu` 的**两排格子都挂在字段 `inventory` 上**，于是两排控件同源同名，
  解析"取第一个"→ 落到容器那排。
- **现在**：`Source` 带嵌套路径（`ItemsToGrabMenu.inventory` vs `inventory`），
  控件有**唯一 id**（`…inventory#12`），重名 → **拒绝**并给出候选（名字 + 屏幕坐标）。

### 3.3 失焦暂停 = 后台完全不能玩

- **现象**：窗口一到后台，**任何**输入方式都无效。
- **根因**：`pause_when_unfocused = true`（我后来在 state 里量到的）让 SDV **失焦时停止更新**——
  没有帧，就没有任何输入处理路径，物理点击、投递消息、直调菜单处理**全部**收不到。
- **现在**：mod 在运行 agent 期间把这个选项按住关掉，并在 `display.pause_when_unfocused` 里报出来。

### 3.4 不抢焦点、不动鼠标

- **现象**：用户："你这还是把我鼠标抢过去了啊 不要跟我抢鼠标！"
- **根因**：**物理鼠标是默认工具**（`SetCursorPos` + `mouse_event`）；
  而且旧代码在 `EnsureWindowActive` 里每次点击前 `SetForegroundWindow`——
  抢了焦点**还丢点击**（Windows 会把"激活窗口"的那一击吃掉）。
- **现在**：物理鼠标**禁用**（`ClickAt` 直接返回 false）；点击=投递/直调；按键后台投递；
  `EnsureWindowActive` 空实现；runner 里每 10 秒的 `focus_window` 删掉。

### 3.5 "这个窗口不读队列"是**可测量的事实**

- **证据**：连续 4 次 `POSTED` 后标题界面纹丝不动；升级到 `MENU_CALL` 后**存档载入成功**。
- **现在**：这个事实存进 `memory/bridge.json` 的 `input.queue_read`，之后**不再付那 3 秒**。
  它是**工具的账**，不是游戏的规律。

### 3.6 同步动作看不到下一帧：判词不许撒谎

- **现象**：直调菜单处理明明把档载进去了，回执却写 `MENU_CALL_NO_CHANGE`（"什么都没变"）。
- **根因**：直调是同步的，但菜单的反应在**下一帧**，而这段代码就跑在**这一帧**里——天生看不到。
- **现在**：判词只说"处理器被调用了、没有 OS 输入参与"，并附
  `"the effect lands on the next frame - the state read that follows is the judge"`。
  这与早上那句把正常拒绝说成"游戏不理人"的 `the game did not react` 是**同一类错误**。

### 3.7 静默的前置阶段看起来就是"死了"

- **现象**：游戏停在标题界面，控制台只有一句 `cycle 1`，几分钟没动静。
- **根因**：开跑前有两道**重审计**（守望者审计会把往期全部日志读回来判读并调模型），
  而且**没有上限、只在失败时打日志**。
- **现在**：推迟到"第一天打完之后"再跑（全新档没有任何东西可判），并且逐条报出在判什么、上限 6 条。

### 3.8 规则是疤痕，数据能替代就删

- **做法**：提示词从 16,760 → 15,536 字符，删掉的是"已被数据替代"的规则：
  `noop 禁令`（尺子替代）、`绝不要编造坐标`（位置现在是数据）、`一天是有限的…别反复试`（尺子+世界模型+守门）、
  `开局的标题菜单怎么点`（那是 harness 的活）。
- **同时修了一处自相矛盾**：`一次只做一个动作` 与新的"排一段玩"直接冲突。

### 3.9 一个字的 bug：f-string 把目标吃掉了

- **现象**：提示词里 `GOAL { }` 是空的——**每次决策都没告诉它今天的目标**。
- **根因**：`STREAMER_SYSTEM` 是 **f-string**，`{{ }}` 在构建时已经被折叠成 `{ }`，
  而替换代码找的是**两个**花括号 → 永不匹配 → 静默丢弃。
- **教训**：提示词管道也需要测试（现在有 `len(system)` 的测量与字符预算）。

### 3.10 桥的缺陷不许被学成游戏知识

- **现象**：agent 自己手写一条"ItemGrabMenu 里同名按钮有两排"当**游戏知识**。
- **现在**：判词属于 `BRIDGE_FAULTS` 时 `worked=None`、跳过 `world.observe`，只进工具账；
  提示词末尾以"**桥自己的记录（不是这个游戏的规律）**"出现。

### 3.11 别替游戏下结论

- 词表：`LOCKED`（门上写着营业时间）、`NOT_FREE`（过场/对话）、`SILENT_NOOP`（命中但游戏有权拒绝）。
- 见证只回答"世界变了吗"；学习只统计**实测**失败（`is False`，不是 `is not True`，否则 `noop`/等待会被误判成失败并封路）。

## 4. 负面清单（被删掉 / 被禁用的东西）

| 东西 | 为什么 |
|---|---|
| 物理鼠标（`SetCursorPos`+`mouse_event`） | 动用户的指针 |
| `EnsureWindowActive` 抢焦点 | 抢焦点还丢点击 |
| runner 每 10 秒 `focus_window` | 同上 |
| 按**名字**点菜单（三处调用点） | 名字对应多个控件时会静默点错 |
| 解析"取第一个匹配" | 把同名的两个控件变成一个硬币 |
| `MENU_CALL_NO_CHANGE` | 自信的错误答案 |
| 开跑前的静默重审计 | 无上限、无日志，看起来像死机 |
| 提示词里被数据替代的规则（4 条） | 每条规则都是每步要付的读题费 |
| `noop` 禁令 / 硬阈值守望 | 尺子已经说了同一件事，而且更准 |

## 6. 重做的建议（给"重做设计"这一轮）

**先立契约，再写代码。** 建议顺序：

1. **动作回执契约**（§DESIGN 2.2）+ **句柄唯一性**（§2.3）先定死，所有调用点必须读回执。
2. **躯体层作为一等公民**：输入 = 一组"工具"，每个工具自带回执与代价；不抢焦点、不动鼠标是硬约束。
   窗口级事实（`queue_read`、`pause_when_unfocused`）**每次会话量一次并记住**。
3. **三本账分离**：游戏知识 / 工具事实 / 项目教训。规矩：桥的缺陷永不进游戏知识。
4. **测量优先**：任何"多久没变化""提示词多大""这一步花了多久"都要能打印出来；规则只保留手册。
5. **裁判在可修改范围之外**：`check_fidelity` / `authenticity` / `bridge.py` 不可被 agent 补丁。
6. **boot 与输入层要有自动化测试**：今天的三个致命 bug 全在这条路上，而它们都靠人肉读日志发现。
7. **不要做**：视觉/OCR、把测量变成阈值、把"某次踩坑"写成规则、agent 直接抢前台或移动鼠标。

**一句话**：这一轮最大的收获不是某个功能，而是**"工具必须自首、事实必须可测、裁判不可被修"**这三条——
它们是重做时的地基。
